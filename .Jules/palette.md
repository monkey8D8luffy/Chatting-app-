## 2024-05-15 - Jetpack Compose Keyboard Submission Side Effects
**Learning:** When mapping `KeyboardActions(onDone = { ... })` in Compose text fields, the default behavior of automatically hiding the soft keyboard is overridden. This causes the keyboard to remain awkwardly visible if an async task (like `isSaving`) begins without explicit navigation. Additionally, pulling submit logic out into a lambda requires careful re-validation of state flags (like `!isSaving`) to prevent the software keyboard from spamming duplicate execution blocks.
**Action:** Always explicitly inject `val keyboardController = LocalSoftwareKeyboardController.current` and call `keyboardController?.hide()` at the top of the custom `onDone` action. Always strictly check loading/disabled state boolean flags directly inside the `submitAction` lambda to prevent keyboard-triggered duplicate submissions.
